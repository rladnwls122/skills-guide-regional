> 문서 유형: how-to

지방대회는 **4시간 안에 8~11개 주요항목을 빠짐없이 처리하는 경기**다. 훈련 목표도 거기에 맞춘다 — 깊은 이해보다 **누락 없는 속도**다.

## 1. 실력 자가 진단

시작 전에 지금 어디쯤인지 잰다. 각 항목을 "손으로 처음부터 끝까지, 문서 없이" 할 수 있는지로 답한다.

| # | 항목 | 기준 시간 |
| --- | --- | --- |
| 1 | VPC + 서브넷 4개 + 라우팅 3개 + NAT + IGW | 20분 |
| 2 | Bastion (IAM role, EIP, 패키지) | 10분 |
| 3 | ALB + 타깃 그룹 + 헬스 체크 통과 | 15분 |
| 4 | ASG (Launch Template, 태그 전파, 스케일 정책) | 20분 |
| 5 | RDS Aurora (포트 변경, KMS, 서브넷 그룹) | 20분 (생성 대기 별도) |
| 6 | ECS 클러스터 + 서비스 + TaskDef + ECR 푸시 | 40분 |
| 7 | EKS 클러스터 + Deployment + Service | 40분 (생성 대기 별도) |
| 8 | CloudWatch 로그 그룹 + 대시보드 + 알람 | 10분 |
| 9 | Secrets Manager + CMK + 앱에서 조회 | 15분 |
| 10 | Lambda + Layer + VPC 배치 | 25분 |

기준 시간의 2배가 넘게 걸리는 항목이 그날의 훈련 대상이다.

## 2. 훈련 단계

### 1단계 — 축 손에 붙이기 (축당 2~3일)

[축 1](/guide/03-axis-network/) ~ [축 5](/guide/07-axis-observability/) 순서로 각 문서의 드릴을 돈다. 한 축을 **세 번 반복**한다.

| 회차 | 방식 | 목적 |
| --- | --- | --- |
| 1회 | 문서 보며 천천히 | 무엇이 무엇에 의존하는지 |
| 2회 | 문서 없이, 막히면 열기 | 순서 기억 |
| 3회 | 시간 재며 | 속도 |

3회차 시간이 기준 시간 안에 들어오면 다음 축으로 간다.

### 2단계 — 과제 통째로 재현 (과제당 하루)

과제지 하나를 골라 **4시간 타이머**를 걸고 처음부터 끝까지 만든다. 끝나면 채점기준표로 자가 채점하고 점수를 기록한다.

순서 추천:

| 순번 | 과제 | 왜 이 순서인가 |
| --- | --- | --- |
| 1 | 2026 1과제 | 최신, 배점 구조가 가장 명확, mark.sh 있음 |
| 2 | 2026 2과제 | 독립형이라 부분 점수 감각을 익히기 좋음 |
| 3 | 2025 1과제 | 컨테이너 축 |
| 4 | 2025 2과제 | 가장 이질적인 4문제 |
| 5 | 2023 1과제 | 가벼운 복습 |
| 6 | 2024 1과제 | 가장 어려움. 여기까지 되면 여유 |
| 7 | 2024 2과제 | CI/CD |
| 8 | 2023 2과제 | ETL |

**같은 과제를 두 번 이상 돌린다.** 1회차는 대개 시간이 모자란다. 2회차에서 시간 안에 들어오는지가 진짜 지표다.

### 3단계 — 변형 훈련

과제지의 이름표·CIDR·포트·리전을 바꿔서 다시 만든다. 손이 이름표를 외워 버리면 실전에서 다른 이름이 나왔을 때 무너진다.

변형 예:

- 2026 1과제의 VPC CIDR을 172.31.0.0/16 / 192.168.0.0/16 으로
- ALB 고정 응답을 403 대신 404로
- RDS 포트를 3307 대신 3399로
- 리전을 도쿄로

### 4단계 — 고장 진단 훈련

동료(또는 자기 자신이 어제 만든 환경)에 고장을 심고 찾는다. 각 축 문서의 "진단" 절이 목록이다.

고장 심기 목록:

| 축 | 심을 고장 |
| --- | --- |
| 네트워크 | private rt의 NAT 경로 삭제 / 서브넷을 잘못된 rt에 연결 / NACL에 deny 추가 |
| Bastion | 인스턴스 프로파일 제거 / 보안 그룹 22 삭제 |
| 컴퓨팅 | 헬스 체크 경로 변경 / 타깃 그룹 포트 변경 / user data 오타 |
| 데이터 | 보안 그룹에서 DB 포트 제거 / secret 값 변경 |
| 관측 | 에이전트 IAM 권한 제거 / 로그 그룹 이름 오타 |

**목표는 5분 안에 원인을 짚는 것.** 대회에서 앱이 안 뜰 때 헤매는 시간이 곧 점수다.

## 3. 4시간 운영 템플릿

### 3-1. 1과제 (통합형)

```
0:00–0:15  문제지 정독. 이름표·CIDR·포트를 표로 옮겨 적는다
           채점기준표가 있으면 항목 수와 배점을 먼저 본다
0:15–0:20  로그 그룹 생성 + 보관 기간          ← 싼 점수 먼저
0:20–0:50  네트워크 전부 (VPC·서브넷·라우팅·NAT·NACL·엔드포인트·Peering)
0:50–1:00  Bastion (user data 자동화)
1:00–1:30  DB 생성 시작 (오래 걸리므로 먼저 건다)
           대기 중에 보안 그룹·Secrets Manager·IAM 준비
1:30–2:30  앱 배포 (ASG/ECS/EKS) + ALB + 타깃 그룹
2:30–2:45  curl 로 POST → GET 왕복 확인       ← 여기가 분기점
2:45–3:15  DB 옵션 훑기 (암호화·백업·로깅·삭제 방지·포트)
3:15–3:35  대시보드 + 알람
3:35–3:50  자가 채점 (mark.sh 또는 채점기준표 명령)
3:50–4:00  잔여 리소스 정리, Bastion 접근 최종 확인
```

**2:45에 앱이 안 뜨면 원인 추적을 30분으로 제한하고, 안 되면 나머지 항목을 줍는다.** 앱 관련 배점은 대개 4.5점 안팎이고, 그 시간에 다른 항목을 채우면 더 얻는다.

### 3-2. 2과제 (독립형)

→ [2과제 카탈로그 C절](/guide/08-task2-catalog/)

### 3-3. 대기 시간을 겹치는 법

생성에 오래 걸리는 리소스를 먼저 건다.

| 리소스 | 대기 |
| --- | --- |
| EKS 클러스터 | 15~20분 |
| Aurora 클러스터 + 인스턴스 | 10~15분 |
| DocumentDB | 10분 |
| ElastiCache | 10분 |
| CloudFront 배포 | 5~15분 |
| NAT Gateway | 2~3분 |
| Client VPN 엔드포인트 | 5~10분 |
| ALB | 2~3분 |

**"만들기 시작 → 다른 일 → 돌아와 확인"** 이 기본 리듬이다. 진행 막대를 쳐다보는 시간이 대회에서 잃는 시간 1위다.

## 4. 준비물 — 대회 전에 만들어 두는 것

### 4-1. 개인 런북

자기 손으로 쓴 CLI 순서 모음. 남의 것을 그대로 쓰면 대회장에서 안 읽힌다.

최소 구성:

```
runbook/
  01-vpc.sh          변수만 바꾸면 도는 VPC 생성 스크립트
  02-bastion.sh      user data 포함
  03-alb.sh          ALB + TG + 리스너 + 규칙
  04-asg.sh          Launch Template + ASG + 스케일 정책
  05-ecs.sh          클러스터 + TaskDef + 서비스
  06-rds.sh          서브넷 그룹 + 클러스터 + 인스턴스
  07-observability.sh 로그 그룹 + 대시보드 + 알람
  99-cleanup.sh      계정 비우기
```

**대회에서 스크립트를 그대로 돌릴 필요는 없다.** 순서를 잊지 않기 위한 참조다. 콘솔이 더 빠른 작업은 콘솔로 한다.

### 4-2. 자가 채점 스크립트

과제별 `mark.sh`. 2024·2026은 실제 배포본이 있고, 2023·2025는 채점기준표의 명령을 옮겨 만든다. → [채점 해부 9절](/guide/02-scoring/)

### 4-3. 정리 스크립트

훈련 사이클마다 계정을 비운다. 잔여 리소스가 채점을 망치는 방식은 [채점 해부 3절](/guide/02-scoring/)에 있다.

### 4-4. 콘솔이 빠른 것과 CLI가 빠른 것

| 콘솔이 빠르다 | CLI가 빠르다 |
| --- | --- |
| CloudWatch 대시보드 위젯 추가 | 로그 그룹 생성·보관 기간 |
| CloudFront 동작(behavior) 설정 | 태그 일괄 부착 |
| Client VPN 엔드포인트 마법사 | 라우팅 경로 추가 |
| Glue Studio 시각 편집기 | 반복적인 describe 확인 |
| ECS 서비스 최초 생성 | 자가 채점 |

**둘을 고집하지 않는다.** 대회 점수는 손이 빠른 쪽으로 얻는다.

## 5. 4시간 모의고사 채점표

과제를 돌 때마다 이 표를 채운다. 시간과 점수를 같이 기록해야 어디서 새는지 보인다.

```
날짜 / 과제:
총점:        / 50 (또는 60)

시각별 진행
  0:30 시점 완료 항목:
  1:30 시점 완료 항목:
  2:30 시점 완료 항목:
  앱 첫 200 응답 시각:

놓친 항목과 원인
  항목번호 | 배점 | 원인(이름표·시간부족·모름·잔여리소스)

다음 회차에 고칠 것 (3개까지)
  1.
  2.
  3.
```

원인을 네 가지로 분류하는 게 핵심이다.

| 원인 | 대응 |
| --- | --- |
| 이름표·오타 | 복사 붙여넣기 습관, 자가 채점 조기 실행 |
| 시간 부족 | 순서 재배치, 대기 겹치기 |
| 모름 | 해당 축 문서로 돌아가 드릴 |
| 잔여 리소스 | 정리 스크립트 |

**"모름"이 아닌 원인이 절반을 넘으면 지식이 아니라 운영이 문제다.** 새 서비스를 공부하지 말고 같은 과제를 한 번 더 돈다.

## 6. 남은 기간별 계획

### 4주 이상

1주차 축 1·2, 2주차 축 3·4·5, 3주차 과제 재현 4개, 4주차 변형·진단·모의고사.

### 2주

- 1~3일: 축 1·2·3 (드릴 3회차까지)
- 4~5일: 축 4·5
- 6~9일: 2026 1·2과제, 2025 1·2과제 재현
- 10~12일: 각 과제 2회차
- 13~14일: 변형·진단·정리 스크립트 점검

### 1주

- 1~2일: 2026 1·2과제 재현 (문서 보며)
- 3~4일: 2025 1·2과제 재현
- 5일: 2026 재도전, 시간 재기
- 6일: 고장 진단 + 자가 채점 스크립트 정비
- 7일: 런북 정리, 계정 비우기, 휴식

### 3일

2026 1과제 → 2026 2과제 → 2025 2과제 순으로 한 번씩. 축 문서는 막힐 때만 연다. **런북과 정리 스크립트만은 반드시 만들어 둔다.**
