> 문서 유형: 개요

지방기능경기대회 클라우드컴퓨팅이 4년간 어떻게 생겨 먹었는지를 한 장에 담는다. 개별 과제 내용은 [기출 분해](/guide/01-past-exams/)에 있다.

## 1. 형식

| 항목 | 2023 | 2024 | 2025 | 2026 |
| --- | --- | --- | --- | --- |
| 과제 수 | 2 | 2 | 2 | 2 |
| 과제당 시간 | 4시간 | 4시간 | 4시간 | 4시간 |
| 1과제 배점 | 60 | 60 | 50 | 50 |
| 2과제 배점 | 40(추정) | 40 | 50 | 50 |
| 1과제 이름 | Web Service Provisioning | Web Service Provisioning | Solution Architecture | Solution architecture |
| 2과제 이름 | Automation | Automation | Small Challenge | Small challenge |

**2023 2과제 배점 40은 추정이다.** 2023 자료 중 확보된 채점기준은 1과제분(60점)뿐이다. 2024가 60/40이고 2과제 항목 수가 비슷해 같은 배분으로 본다.

전국대회는 3과제 체제이지만 지방은 4년 내내 2과제다. 그래서 훈련 단위도 "4시간 안에 과제 하나를 끝낸다"가 된다.

## 2. 두 번의 전환점

### 2-1. 2025 — 2과제가 파이프라인에서 독립 4문제로 바뀌었다

2023·2024의 2과제는 **하나의 파이프라인**이었다. 2023은 API Gateway → Kinesis → S3 → Glue 로 이어지는 ETL 한 줄기, 2024는 CodeCommit → CodeBuild → CodeDeploy → CodePipeline 로 이어지는 CI/CD 한 줄기다. 앞 단계가 막히면 뒤가 통째로 죽는다.

2025부터는 **서로 독립된 소문제 4개**가 되었고 각 12.5점으로 균등 배분된다. 2025는 Client VPN / KEDA / Terraform / EC2 자동화, 2026은 EFS / Athena / IAM / Lambda 다. 네 문제 사이에 의존이 없다.

전략이 완전히 달라진다.

- 파이프라인형(2023·2024): 앞부터 순서대로. 중간에 막히면 그 뒤는 포기하고 다른 축으로 넘어간다.
- 독립형(2025·2026): **12.5점씩 네 덩어리라 가장 자신 있는 것부터 집는다.** 한 문제에 1시간을 넘기면 손을 뗀다. 4시간 ÷ 4문제 = 문제당 60분이 기준선이다.

### 2-2. 2026 — 2과제 채점이 Bastion을 떠나 CloudShell로 갔다

2023~2025는 1·2과제 모두 선수가 만든 Bastion EC2에 SSH로 붙어 채점했다. 2026 2과제 채점기준은 다르다.

> 채점시 cloud shell을 이용해 진행합니다. 브라우저를 통해 접근하며 권한 및 접속 문제가 없도록 주의합니다. — 2026 2과제 과제지 유의사항 10)

2026 2과제에는 Bastion 요구 자체가 없다. 1과제는 여전히 `worldpay-bastion` 을 요구하고 SSH·SSM 접근을 전제한다.

의미는 둘이다. 첫째, 2과제에서 Bastion 만드는 시간을 아낀다. 둘째, **CloudShell 은 리전마다 새로 열린다** — 2026 2과제는 문제마다 리전이 달라(EFS는 도쿄, 나머지는 서울) 채점자가 리전을 옮겨 다니며 채점한다. 리전을 잘못 쓰면 리소스가 있어도 안 보인다.

## 3. 채점 흐름

4년 내내 같은 골격이다.

```
1) 채점자가 선수 Bastion(또는 CloudShell)에 접속
2) aws sts get-caller-identity 로 선수 계정인지 확인   ← 다른 계정이면 부정행위 의심
3) ~/.aws/config 에 region=ap-northeast-2, output=json 설정
4) 채점기준표의 항목 번호 순서대로 aws CLI 명령 실행
5) 출력이 기대값과 같으면 득점
```

핵심은 4)다. **채점은 사람이 콘솔을 눈으로 보는 게 아니라 정해진 CLI 명령의 출력 문자열을 대조하는 것이다.** 2024·2026은 아예 그 명령을 그대로 담은 `mark.sh` 를 채점자에게 배포한다.

여기서 나오는 규칙이 이 문서 전체를 관통한다 — [채점 해부](/guide/02-scoring/)에서 항목별로 다룬다.

## 5. 지방과 전국의 차이

| | 지방 | 전국 |
| --- | --- | --- |
| 과제 수 | 2 | 3 |
| 과제당 시간 | 4시간 | 4시간+ |
| 한 과제의 서비스 수 | 많음 (8~11개 주요항목) | 적고 깊음 |
| 요구 깊이 | 서비스 기본 옵션 수준 | Suricata 룰 직접 작성, ArgoCD Rollouts 등 |
| IaC | 2025 2과제에서 Terraform 1회 | 상시 |
| 채점 | CLI 출력 대조 | 동일 |

지방 훈련에서 시간을 잘못 쓰는 대표적 방식이 **전국 수준의 깊이를 지방 축에 쏟는 것**이다. 지방은 "DocumentDB의 감사 로그를 켠다"까지지 "감사 로그를 파싱해 이상 탐지를 만든다"가 아니다. 옵션 하나하나를 빠르게 켜는 손이 점수다.
