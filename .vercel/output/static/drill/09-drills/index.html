훈련 계획과 드릴

문서 유형: how-to

지방대회는 4시간 안에 8~11개 주요항목을 빠짐없이 처리하는 경기다. 훈련 목표도 거기에 맞춘다 — 깊은 이해보다 누락 없는 속도다.

1. 실력 자가 진단

섹션 제목: “1. 실력 자가 진단”

시작 전에 지금 어디쯤인지 잰다. 각 항목을 “손으로 처음부터 끝까지, 문서 없이” 할 수 있는지로 답한다.

#항목기준 시간
1VPC + 서브넷 4개 + 라우팅 3개 + NAT + IGW20분
2Bastion (IAM role, EIP, 패키지)10분
3ALB + 타깃 그룹 + 헬스 체크 통과15분
4ASG (Launch Template, 태그 전파, 스케일 정책)20분
5RDS Aurora (포트 변경, KMS, 서브넷 그룹)20분 (생성 대기 별도)
6ECS 클러스터 + 서비스 + TaskDef + ECR 푸시40분
7EKS 클러스터 + Deployment + Service40분 (생성 대기 별도)
8CloudWatch 로그 그룹 + 대시보드 + 알람10분
9Secrets Manager + CMK + 앱에서 조회15분
10Lambda + Layer + VPC 배치25분

기준 시간의 2배가 넘게 걸리는 항목이 그날의 훈련 대상이다.

2. 훈련 단계

섹션 제목: “2. 훈련 단계”

1단계 — 축 손에 붙이기 (축당 2~3일)

섹션 제목: “1단계 — 축 손에 붙이기 (축당 2~3일)”

축 1 ~ 축 5 순서로 각 문서의 드릴을 돈다. 한 축을 세 번 반복한다.

회차방식목적
1회문서 보며 천천히무엇이 무엇에 의존하는지
2회문서 없이, 막히면 열기순서 기억
3회시간 재며속도

3회차 시간이 기준 시간 안에 들어오면 다음 축으로 간다.

2단계 — 과제 통째로 재현 (과제당 하루)

섹션 제목: “2단계 — 과제 통째로 재현 (과제당 하루)”

과제지 하나를 골라 4시간 타이머를 걸고 처음부터 끝까지 만든다. 끝나면 채점기준표로 자가 채점하고 점수를 기록한다.

순서 추천:

순번과제왜 이 순서인가
12026 1과제최신, 배점 구조가 가장 명확, mark.sh 있음
22026 2과제독립형이라 부분 점수 감각을 익히기 좋음
32025 1과제컨테이너 축
42025 2과제가장 이질적인 4문제
52023 1과제가벼운 복습
62024 1과제가장 어려움. 여기까지 되면 여유
72024 2과제CI/CD
82023 2과제ETL

같은 과제를 두 번 이상 돌린다. 1회차는 대개 시간이 모자란다. 2회차에서 시간 안에 들어오는지가 진짜 지표다.

3단계 — 변형 훈련

섹션 제목: “3단계 — 변형 훈련”

과제지의 이름표·CIDR·포트·리전을 바꿔서 다시 만든다. 손이 이름표를 외워 버리면 실전에서 다른 이름이 나왔을 때 무너진다.

변형 예:

  • 2026 1과제의 VPC CIDR을 172.31.0.0/16 / 192.168.0.0/16 으로
  • ALB 고정 응답을 403 대신 404로
  • RDS 포트를 3307 대신 3399로
  • 리전을 도쿄로

4단계 — 고장 진단 훈련

섹션 제목: “4단계 — 고장 진단 훈련”

동료(또는 자기 자신이 어제 만든 환경)에 고장을 심고 찾는다. 각 축 문서의 “진단” 절이 목록이다.

고장 심기 목록:

축심을 고장
네트워크private rt의 NAT 경로 삭제 / 서브넷을 잘못된 rt에 연결 / NACL에 deny 추가
Bastion인스턴스 프로파일 제거 / 보안 그룹 22 삭제
컴퓨팅헬스 체크 경로 변경 / 타깃 그룹 포트 변경 / user data 오타
데이터보안 그룹에서 DB 포트 제거 / secret 값 변경
관측에이전트 IAM 권한 제거 / 로그 그룹 이름 오타

목표는 5분 안에 원인을 짚는 것. 대회에서 앱이 안 뜰 때 헤매는 시간이 곧 점수다.

3. 4시간 운영 템플릿

섹션 제목: “3. 4시간 운영 템플릿”

3-1. 1과제 (통합형)

섹션 제목: “3-1. 1과제 (통합형)”

아래 타이머가 이 구간표를 그대로 돌린다. 훈련할 때 시작 버튼을 누르고 현재 구간이 어디인지 보며 연습한다. 진행은 브라우저에만 남고 탭을 닫아도 시작 시각 기준으로 이어진다.

2:45에 앱이 안 뜨면 원인 추적을 30분으로 제한하고, 안 되면 나머지 항목을 줍는다. 앱 관련 배점은 대개 4.5점 안팎이고, 그 시간에 다른 항목을 채우면 더 얻는다.

3-2. 2과제 (독립형)

섹션 제목: “3-2. 2과제 (독립형)”

→ 2과제 카탈로그 C절

3-3. 대기 시간을 겹치는 법

섹션 제목: “3-3. 대기 시간을 겹치는 법”

생성에 오래 걸리는 리소스를 먼저 건다.

리소스대기
EKS 클러스터15~20분
Aurora 클러스터 + 인스턴스10~15분
DocumentDB10분
ElastiCache10분
CloudFront 배포5~15분
NAT Gateway2~3분
Client VPN 엔드포인트5~10분
ALB2~3분

“만들기 시작 → 다른 일 → 돌아와 확인” 이 기본 리듬이다. 진행 막대를 쳐다보는 시간이 대회에서 잃는 시간 1위다.

4. 준비물 — 대회 전에 만들어 두는 것

섹션 제목: “4. 준비물 — 대회 전에 만들어 두는 것”

4-1. 개인 런북

섹션 제목: “4-1. 개인 런북”

자기 손으로 쓴 CLI 순서 모음. 남의 것을 그대로 쓰면 대회장에서 안 읽힌다.

최소 구성:

대회에서 스크립트를 그대로 돌릴 필요는 없다. 순서를 잊지 않기 위한 참조다. 콘솔이 더 빠른 작업은 콘솔로 한다.

4-2. 자가 채점 스크립트

섹션 제목: “4-2. 자가 채점 스크립트”

과제별 mark.sh. 2024·2026은 실제 배포본이 있고, 2023·2025는 채점기준표의 명령을 옮겨 만든다. → 채점 해부 9절

4-3. 정리 스크립트

섹션 제목: “4-3. 정리 스크립트”

훈련 사이클마다 계정을 비운다. 잔여 리소스가 채점을 망치는 방식은 채점 해부 3절에 있다.

4-4. 콘솔이 빠른 것과 CLI가 빠른 것

섹션 제목: “4-4. 콘솔이 빠른 것과 CLI가 빠른 것”
콘솔이 빠르다CLI가 빠르다
CloudWatch 대시보드 위젯 추가로그 그룹 생성·보관 기간
CloudFront 동작(behavior) 설정태그 일괄 부착
Client VPN 엔드포인트 마법사라우팅 경로 추가
Glue Studio 시각 편집기반복적인 describe 확인
ECS 서비스 최초 생성자가 채점

둘을 고집하지 않는다. 대회 점수는 손이 빠른 쪽으로 얻는다.

5. 4시간 모의고사 채점표

섹션 제목: “5. 4시간 모의고사 채점표”

과제를 돌 때마다 이 표를 채운다. 시간과 점수를 같이 기록해야 어디서 새는지 보인다.

원인을 네 가지로 분류하는 게 핵심이다.

원인대응
이름표·오타복사 붙여넣기 습관, 자가 채점 조기 실행
시간 부족순서 재배치, 대기 겹치기
모름해당 축 문서로 돌아가 드릴
잔여 리소스정리 스크립트

“모름”이 아닌 원인이 절반을 넘으면 지식이 아니라 운영이 문제다. 새 서비스를 공부하지 말고 같은 과제를 한 번 더 돈다.

6. 남은 기간별 계획

섹션 제목: “6. 남은 기간별 계획”

4주 이상

섹션 제목: “4주 이상”

1주차 축 1·2, 2주차 축 3·4·5, 3주차 과제 재현 4개, 4주차 변형·진단·모의고사.

2주

섹션 제목: “2주”
  • 1~3일: 축 1·2·3 (드릴 3회차까지)
  • 4~5일: 축 4·5
  • 6~9일: 2026 1·2과제, 2025 1·2과제 재현
  • 10~12일: 각 과제 2회차
  • 13~14일: 변형·진단·정리 스크립트 점검

1주

섹션 제목: “1주”
  • 1~2일: 2026 1·2과제 재현 (문서 보며)
  • 3~4일: 2025 1·2과제 재현
  • 5일: 2026 재도전, 시간 재기
  • 6일: 고장 진단 + 자가 채점 스크립트 정비
  • 7일: 런북 정리, 계정 비우기, 휴식

3일

섹션 제목: “3일”

2026 1과제 → 2026 2과제 → 2025 2과제 순으로 한 번씩. 축 문서는 막힐 때만 연다. 런북과 정리 스크립트만은 반드시 만들어 둔다.
